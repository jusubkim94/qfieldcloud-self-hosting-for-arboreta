# 버전 고정 정책

## 목표

동일한 입력이 동일한 소프트웨어를 배포하도록 공급망을 재현 가능하게 만듭니다. 새 버전 발견과 운영 반영을 분리하며 자동 운영 업데이트는 허용하지 않습니다.

## 확인할 식별자

1. QFieldCloud 공식 릴리스 태그
2. 태그가 가리키는 전체 Git 커밋 SHA
3. 공식 빌드 워크플로에서 게시된 컨테이너인지 여부
4. 대상 플랫폼의 이미지 digest
5. 외부 컨테이너와 다운로드 아티팩트의 버전 및 checksum

태그는 사람이 읽기 쉬운 이름이고 digest는 실제 이미지 내용을 고정합니다. 둘을 함께 기록합니다. 브랜치 이름, 변동 태그, 메이저 버전만 적은 이미지 참조는 운영 입력으로 허용하지 않습니다.

## 사실·추론·권고

- **확인된 사실:** 공식 저장소는 릴리스 이벤트에서 app, worker wrapper, QGIS worker와 Nginx 이미지를 게시하는 워크플로를 운영합니다.
- **프로젝트 추론:** 태그만 사용하면 레지스트리 변경이나 플랫폼 차이를 놓칠 수 있습니다.
- **프로젝트 권고:** 검증 매니페스트에 릴리스, commit, `linux/amd64` digest와 검증일을 기록하고 Pull Request에서 사람이 검토합니다.

## 업데이트 승인 절차

1. 공식 릴리스 노트와 라이선스 변경 확인
2. 태그와 commit 대응 검증
3. 모든 이미지의 플랫폼 digest 기록
4. DB migration과 호환성 검토
5. 비운영 환경에서 설치·상태·worker 작업 시험
6. 백업과 롤백 시험
7. 결과를 Pull Request에 기록
8. 사용자의 명시적 운영 반영 승인

검증 실패, 이미지 누락 또는 출처 불일치 시 기존 검증 버전을 유지합니다. 이 Phase에서는 정책만 작성하며 버전 매니페스트나 자동 검사 도구를 구현하지 않습니다.
