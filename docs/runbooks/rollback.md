# 롤백 실행서

`rollback`이라는 말은 서로 다른 상황을 가리킬 수 있습니다. 이 파일럿에서 가능한 범위를 구분해야 합니다.

## 1. CloudFormation 생성 실패 뒤 자동 정리

CloudFormation은 생성 실패 뒤 만든 자원을 되돌리려고 시도할 수 있습니다. 그러나 `ROLLBACK_COMPLETE`는 서비스가 정상이라는 뜻이 아니며, `ROLLBACK_FAILED`나 중간 오류가 있으면 자원이 남을 수 있습니다.

1. AWS 웹 콘솔에서 **Asia Pacific (Seoul) ap-northeast-2**를 선택합니다.
2. **CloudFormation → Stacks → qfieldcloud-pilot → Events**를 엽니다.
3. 최초 실패 원인과 현재 상태를 확인합니다.
4. **Resources**에서 생성되었거나 삭제에 실패한 자원을 확인합니다.
5. **Lightsail → Instances / Networking → Static IPs / Alarms**도 각각 확인합니다.
6. 조사를 끝냈다면 [삭제 실행서](uninstall.md)에 따라 남은 자원을 제거합니다.

실패한 인스턴스는 월 **US$24** 비용이 계속 발생할 수 있고, 분리된 고정 IP는 시간당 **US$0.005**가 청구될 수 있습니다.

## 2. 이전 애플리케이션 릴리스로 되돌리기

제자리 릴리스 롤백은 지원하지 않습니다. 데이터가 전혀 필요 없는 파일럿에 한해서만 현재 스택을 완전히 삭제한 뒤, 이전에 검증된 릴리스의 고정 S3 객체 버전으로 새 빈 `qfieldcloud-pilot`을 만들 수 있습니다.

이 작업은 서버 교체이지 데이터 복구가 아닙니다. 이전 릴리스도 `main`, `master`, `latest`가 아니라 고정 commit, checksum과 S3 `versionId`를 사용해야 합니다.

## 3. 데이터 롤백

이 파일럿에는 자동 스냅샷, 애플리케이션 백업 또는 데이터 복구 작업이 없습니다. 따라서 데이터베이스나 객체 파일을 과거 시점으로 되돌리는 기능은 없습니다.

- 스택, 인스턴스 또는 디스크를 삭제한 뒤에는 QFieldCloud 데이터를 복구할 수 없습니다.
- 생성 실패 중 디스크가 손상되거나 삭제되어도 자동 복구 지점은 없습니다.
- 상태가 정상이라는 사실은 복구 사본이 있다는 뜻이 아닙니다.

데이터 복구가 필요할 수 있는 운영 환경에는 이 파일럿을 사용하지 마세요. 복구 지점, 복구 시험과 데이터 이전 절차가 설계된 별도 운영 구성이 필요합니다.

현재 S3 릴리스 artifact는 게시되지 않았고, 위 실패 정리와 이전 릴리스 재생성 흐름은 실제 AWS에서 아직 검증하지 않았습니다.
