# 롤백 실행서 설계

## 시작 조건

업데이트 전부터 이전 이미지 digest, DB 복구 지점, 객체 버전과 설정 사본이 준비되어 있어야 합니다. 장애가 발생한 뒤 처음 롤백 방법을 설계하지 않습니다.

## 판단 순서

1. 영향 범위와 마지막 정상 시각 확인
2. 쓰기 중단 필요 여부 결정
3. 앱만 되돌릴지 DB·객체도 복원할지 결정
4. migration의 역호환성 확인
5. 예상 데이터 손실 구간을 사용자에게 설명
6. 승인 후 격리 검증 또는 운영 롤백
7. 상태·worker·데이터 일관성 검사
8. 원인과 재발 방지 기록

DB를 과거로 복원하면 그 이후 변경이 손실될 수 있습니다. snapshot 또는 dump의 존재만으로 롤백 성공을 보장하지 않습니다. 파괴적인 복원은 별도 승인을 받아야 합니다.
