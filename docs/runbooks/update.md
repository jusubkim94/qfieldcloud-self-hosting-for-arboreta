# 업데이트 실행서

## 결론

`lab-lightsail` 원클릭 파일럿은 새 스택 생성만 지원합니다. 실행 중인 `qfieldcloud-pilot`을 제자리에서 업데이트하는 절차는 제공하지 않습니다.

> 자동 스냅샷, 애플리케이션 백업, 데이터 이전 기능이 없습니다. 데이터가 들어 있는 파일럿을 삭제하고 새 버전으로 다시 만들면 기존 데이터는 영구 손실됩니다.

## 릴리스 버전이 바뀌는 방식

프로젝트 유지관리자는 새 버전을 공개하기 전에 다음을 수행해야 합니다.

1. 공식 QFieldCloud 릴리스와 전체 commit을 확인합니다.
2. 모든 실행 이미지 digest와 다운로드 checksum을 고정합니다.
3. 릴리스별 `template.yaml`, `manifest.json`, `SHA256SUMS`를 생성합니다.
4. 변경되지 않는 S3 객체 버전으로 게시한 뒤 checksum과 익명 읽기를 다시 확인합니다.
5. 고정된 S3 `versionId`를 사용하는 새 Quick Create 링크를 공개합니다.

`main`, `master`, `latest`, 태그만 있는 이미지 또는 만료되는 서명 URL은 업데이트 입력으로 사용하지 않습니다. 자세한 기준은 [버전 고정 정책](../version-policy.md)을 따릅니다.

## 사용자가 할 수 있는 작업

현재 파일럿이 비어 있고 삭제해도 되는 경우에만 다음 순서를 사용합니다.

1. 현재 스택의 릴리스 버전과 필요한 기록을 확인합니다.
2. 데이터 영구 손실과 월 **US$24** 자원 재생성을 다시 승인합니다.
3. [삭제 실행서](uninstall.md)에 따라 기존 `qfieldcloud-pilot`과 잔존 자원을 완전히 삭제합니다.
4. 새 릴리스의 활성화된 버튼에서 [설치 실행서](install.md)를 다시 수행합니다.
5. [상태 확인](status.md) 전체를 다시 수행합니다.

데이터를 보존해야 한다면 이 파일럿에서 업데이트하지 마세요. 데이터 내보내기, 이전, 검증과 되돌리기 계획을 갖춘 별도 운영 설계가 먼저 필요합니다.

현재 릴리스 artifact는 S3에 게시되지 않았고 실제 Quick Create 설치, 제자리 업데이트, 교체 설치 모두 실제 AWS에서 검증하지 않았습니다.
