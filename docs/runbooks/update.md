# 업데이트 실행서 설계

운영 환경은 새 릴리스를 자동 반영하지 않습니다.

## 승인 흐름

1. 공식 릴리스 노트와 보안 공지 확인
2. 릴리스 태그·전체 commit·플랫폼 이미지 digest 확인
3. 외부 의존성과 라이선스 변경 확인
4. DB migration과 되돌리기 가능성 검토
5. 현재 DB와 객체 백업
6. 비운영 환경 업데이트
7. 상태 endpoint와 작은 프로젝트 worker 시험
8. 격리 복원과 롤백 시험
9. 결과·중단시간·비용 영향을 Pull Request에 기록
10. 사용자 승인 후 운영 반영

검증하지 않은 버전, 변동 참조 또는 출처가 불분명한 이미지는 사용하지 않습니다. DB migration이 적용되면 이미지만 이전 것으로 바꾸는 단순 되돌리기가 안전하지 않을 수 있습니다.
