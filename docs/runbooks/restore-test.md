# 복원시험 실행서 설계

## 절대 원칙

운영 DB나 기존 식물이력관리 DB 위에 복원시험을 수행하지 않습니다. 격리된 시험 DB와 시험 객체 저장소를 사용하고, 비용이 생기는 자원은 사전 설명과 승인 후에만 만듭니다.

## 순서

1. 복원할 백업, 시각과 QFieldCloud 버전 선택
2. checksum과 암호화 키 접근 가능 여부 확인
3. 격리된 시험 대상과 삭제 계획 검토
4. DB 복원 후 schema와 migration 상태 확인
5. 객체 복원 후 누락·크기 검사
6. `/api/v1/status/` 확인
7. 시험 사용자와 작은 프로젝트 확인
8. worker 작업 실행
9. 복원 시간, 오류와 데이터 손실 범위 기록
10. 승인된 시험 자원만 안전하게 삭제

## 완료기준

DB·storage 상태, 프로젝트 파일 조회와 worker 작업이 모두 정상이어야 합니다. 실패한 복원시험은 백업 성공으로 표시하지 않고 원인과 다음 조치를 기록합니다.
