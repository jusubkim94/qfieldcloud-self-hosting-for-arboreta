# 안전한 삭제 실행서 설계

## 1단계: 삭제 계획

다음 항목을 사용자에게 보여주고 승인을 받습니다.

- AWS 계정 별칭과 리전
- 삭제할 스택과 자원 목록
- QFieldCloud 전용 DB snapshot 보존 여부
- S3 또는 로컬 객체 백업 보존 여부
- 로그와 인증서 보존 여부
- 삭제 후 복구 가능 여부와 예상 잔존 비용

기존 식물이력관리 DB는 삭제 목록에 포함될 수 없습니다.

## 2단계: 사전 검사

마지막 백업 checksum과 복원시험 결과를 확인합니다. 삭제 보호가 있는 자원과 CloudFormation 밖에서 만든 자원을 구분합니다. 인스턴스 정지만으로 과금이 끝난다고 가정하지 않습니다.

## 3단계: 명시적 삭제

자동화는 스택 이름과 리전을 다시 보여주고 명시적 확인을 요구해야 합니다. 기본 동작은 계획 표시이며, 강제 확인 생략 옵션을 제공하지 않는 것을 권고합니다.

## 4단계: 잔존 자원 확인

스냅샷, 디스크, RDS, S3 객체 버전, 로드 밸런서, 고정 IP, CloudWatch 로그, DNS와 인증서를 확인합니다. 보존 자원에는 소유자, 만료일과 월 예상 비용을 기록합니다.

Phase 1에서는 실제 삭제 명령이나 자동화를 제공하지 않습니다.
