# 삭제 실행서

이 절차는 `qfieldcloud-pilot` 스택과 그 파일럿 자원을 AWS 웹 콘솔에서 삭제하는 방법입니다.

> 자동 스냅샷과 애플리케이션 백업이 없습니다. 스택, 인스턴스 또는 디스크를 삭제하면 서버 안의 QFieldCloud 데이터가 영구 손실되며 이 저장소의 기능으로 복구할 수 없습니다.

## 1. 삭제 전에 멈춰서 확인

- 오른쪽 위 리전이 **Asia Pacific (Seoul) ap-northeast-2**인지 확인합니다.
- 삭제 대상이 스택 `qfieldcloud-pilot`인지 확인합니다.
- 이 파일럿의 데이터가 더 이상 필요하지 않다는 사용자의 명시적 승인을 받습니다.
- 기존 식물이력관리 PostGIS 데이터베이스는 삭제 대상이 아닙니다.
- 조사할 실패 로그가 필요하면 Secret과 사용자 데이터를 가린 뒤 먼저 기록합니다.

데이터가 필요할 가능성이 조금이라도 있으면 삭제하지 마세요. 이 파일럿에는 삭제 전 데이터를 안전하게 보존하는 자동 절차가 없습니다.

## 2. CloudFormation 스택 삭제

1. AWS 웹 콘솔에서 **CloudFormation**을 엽니다.
2. 왼쪽 메뉴에서 **Stacks**를 누릅니다.
3. 목록에서 `qfieldcloud-pilot`을 선택합니다.
4. **Resources** 탭을 열어 인스턴스, 고정 IP, 상태 알람 등 삭제될 대상을 확인합니다.
5. 삭제 보호를 사용자가 별도로 켰다면 **Stack actions → Edit termination protection → Disable**을 선택합니다.
6. **Delete**를 누릅니다.
7. 확인 창에 `qfieldcloud-pilot`이 표시되는지 다시 확인한 뒤 **Delete**를 누릅니다.
8. **Events**에서 삭제 과정을 확인합니다. `DELETE_COMPLETE`가 되면 기본 목록에서 스택이 사라질 수 있습니다.

`DELETE_FAILED`이면 먼저 **Events**의 실패 원인을 확인합니다. CloudFormation 밖에서 자원을 수동으로 지우거나 강제 삭제를 시도하기 전에 남길 데이터, 종속 자원과 비용 영향을 다시 검토합니다.

## 3. Lightsail 잔존 자원 확인

스택 삭제 성공만 보고 과금이 모두 끝났다고 단정하지 않습니다.

1. AWS 콘솔에서 **Lightsail**을 엽니다.
2. **Instances**에서 `qfieldcloud-pilot`이 없는지 확인합니다.
3. **Networking → Static IPs**에서 이 파일럿의 고정 IP가 없는지 확인합니다.
4. **Storage → Disks**에서 분리된 디스크가 없는지 확인합니다.
5. **Snapshots**에서 사용자가 별도로 만든 수동 스냅샷이 없는지 확인합니다. 템플릿 자체는 스냅샷을 만들지 않습니다.
6. **Alarms**에서 파일럿의 상태 알람이 없는지 확인합니다.

특히 인스턴스와 연결되지 않은 고정 IP는 시간당 **US$0.005**가 청구됩니다. 남아 있다면 소유 관계를 확인한 뒤 삭제해야 합니다. 다른 환경의 자원인지 확실하지 않으면 삭제하지 말고 AWS 관리자에게 확인합니다.

## 4. 비용 종료 확인

1. AWS 콘솔에서 **Billing and Cost Management → Bills**를 엽니다.
2. 현재 월의 **Amazon Lightsail** 항목을 확인합니다.
3. 비용 반영에는 시간이 걸릴 수 있으므로 다음 청구 내역에서도 잔존 사용량을 다시 확인합니다.

이 템플릿은 별도 IAM 사용자나 역할을 만들지 않으므로 이 파일럿 때문에 삭제할 전용 로그인 주체는 없습니다. 공개 S3 릴리스도 만들지 않으며, 이 전체 삭제 흐름은 실제 AWS에서 아직 종단 간 검증하지 않았습니다.
