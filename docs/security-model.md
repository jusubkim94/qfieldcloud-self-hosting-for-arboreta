# 보안 모델

## 보호 대상

사용자 계정, 프로젝트 파일, QFieldCloud 시스템 DB, 암호화 키, DB 비밀번호, 객체 저장소 권한, 작업용 임시 토큰, TLS 개인키와 ACME 계정 상태를 보호합니다. 기존 식물이력관리 DB는 이 배포기가 접근하지 않는 별도 보안 경계입니다.

## 확인된 사실

- 공식 worker wrapper는 임시 QGIS worker를 만들기 위해 Docker API를 사용합니다.
- 공식 Compose는 호스트의 Docker socket을 worker wrapper에 마운트합니다.
- 현재 파일럿의 Ofelia 작업 스케줄러도 Docker label을 읽고 `runcrons`를 실행하기 위해 같은 socket을 사용합니다. `:ro` 마운트는 Docker API를 읽기 전용으로 제한하지 않습니다.
- Docker socket 제어는 호스트 파일 마운트와 관리자 수준 컨테이너 생성으로 이어질 수 있어 매우 민감합니다.
- QFieldCloud 상태 endpoint는 DB와 객체 저장소 연결 상태를 확인하지만 전체 보안이나 백업 성공을 증명하지 않습니다.
- 기본 인증서 모드는 실제 AWS 검증 이력이 있는 `self-signed`입니다. 선택 `letsencrypt-ip` 구현은 고정 IPv4, Let’s Encrypt 160시간 short-lived 인증서와 HTTP-01을 사용하지만 현재 AWS 스택에 적용하지 않았고 실제 발급·갱신 종단 간 검증 전입니다.

## 프로젝트 권고

### 인증정보

- GitHub, 템플릿 URL, 예제 파일과 로그에 Secret을 넣지 않습니다.
- `lab-lightsail` worker 시험은 관리자 비밀번호나 일반 로그인 세션을 사용하지 않고, 서버 내부에서 만든 1시간짜리 시험 전용 토큰만 사용한 뒤 그 토큰 하나를 폐기합니다.
- 서버 전원 차단이나 `SIGKILL`로 정리 절차가 실행되지 못하면 root 전용 시험 임시 파일이 남을 수 있습니다. 토큰은 1시간 후 만료되고 다음 시험이 같은 용도의 기존 DB 토큰을 폐기하지만, 남은 파일은 운영자가 점검해야 합니다.
- `standard-aws`는 IAM 역할과 Secrets Manager를 사용합니다.
- Secret 값은 출력하지 않고 존재 여부와 마지막 교체 시각만 진단합니다.
- 노출된 값은 삭제만 하지 않고 즉시 폐기·교체합니다.

### Docker 호스트

- Docker API를 인터넷 TCP 포트로 공개하지 않습니다.
- worker wrapper와 QGIS worker 이미지를 digest로 고정합니다.
- 예상하지 않은 컨테이너 생성과 권한 상승을 로그로 감시합니다.
- 장기적으로 worker 전용 EC2 분리를 검토합니다.

### 네트워크와 HTTPS

- DB와 객체 저장소 관리 포트를 인터넷에 공개하지 않습니다.
- RDS public access를 끄고 보안 그룹을 앱 호스트로 제한합니다.
- S3 public access block과 기본 암호화를 사용합니다.
- 일반 사용자는 공인 인증서가 적용된 HTTPS로만 로그인합니다.
- 자체 서명 인증서는 폐쇄 시험에서 신뢰 CA 배포 절차가 있을 때만 사용합니다.
- `letsencrypt-ip`은 기존 공개 TCP 80의 `/.well-known/acme-challenge/` 경로로 HTTP-01 소유 검증을 수행하며 새 AWS 포트·자원·권한을 추가하지 않습니다. DB와 객체 저장소 관리 포트는 계속 비공개입니다.
- Let’s Encrypt 발급·갱신은 CA, 공개 인터넷과 rate limit이라는 AWS 밖 신뢰·가용성 경계를 추가합니다. 공인 인증서가 있다고 애플리케이션 자체가 안전하거나 운영 준비가 끝났다고 판단하지 않습니다.
- 공인 모드의 systemd timer는 6시간 간격과 최대 45분 무작위 지연으로 확인하고 만료 48시간보다 많은 후보만 받습니다. 후보 CA chain, 현재 IP SAN, 인증서·개인키 일치와 Nginx live 응답을 검증한 뒤에만 `current` link를 원자 전환합니다.
- 최초 공인 인증서 발급이 실패하면 설치 성공을 보고하지 않습니다. 갱신 또는 Nginx reload가 실패하면 검증된 이전 인증서로 되돌리고 root 전용 실패 표식을 남기며, 자체서명 인증서로 조용히 대체하지 않습니다.
- HTTP-01을 제공할 Nginx를 시작하기 위해 공인 모드 설치 중 임시 자체서명 IP 인증서가 존재할 수 있습니다. 이 임시 재료는 외부 신뢰를 뜻하지 않고 공인 인증서 검증·전환 전에는 완료 신호를 보낼 수 없습니다.
- Certbot 이미지와 보고된 버전은 각각 고정 digest와 `5.7.0`이어야 합니다. Certbot 유지관리 컨테이너에는 Docker socket이나 자체 공개 포트를 주지 않습니다.

### 데이터 최소화

원본 드론 정사영상은 기본 저장 대상에서 제외합니다. 로그에는 전체 환경변수, 인증 헤더, 프로젝트 Secret과 DB 접속 문자열을 기록하지 않습니다. ACME 계정·발급 이력·개인키와 원본 Certbot 로그는 root 전용이며 일반 애플리케이션 백업과 공개 진단본에서 제외합니다. 서버 전체 snapshot은 이 상태를 포함할 수 있으므로 Secret과 같은 접근 통제를 적용합니다.

### AWS 배포 권한

- 권장 경로는 `qfieldcloud-lab-access` CloudFormation 스택이 만드는 고정 배포 역할입니다. 같은 최소 권한 정책을 역할에 연결하고 permissions boundary(권한 상한선)로도 적용합니다. 발급된 각 역할 자격증명은 최대 1시간이지만 로컬 역할 프로필은 계속 남고, 원본 브라우저 로그인이 유효하면 새 1시간 세션을 다시 받을 수 있습니다.
- 권한 준비는 비루트 계정 관리자가 수행하고 실제 설치자는 별도 IAM Identity Center 또는 `aws login` 브라우저 임시 세션에서 역할을 맡는 구성을 권장합니다. 한 사람이 관리자 프로필을 원본으로 재사용하면 역할을 맡은 호출만 제한될 뿐 원본 관리자 세션의 권한은 사라지지 않습니다. Access Key, 비밀번호와 토큰은 로컬 역할 프로필에 저장하지 않습니다.
- 신뢰 주체가 IAM 사용자이면 권한 준비 시점에 장기 Access Key가 없고 MFA 장치가 등록되어 있음을 확인합니다. 신뢰 정책이 매 `AssumeRole` 요청에 MFA 사용을 조건으로 강제하는 것은 아니며, 이후 Access Key를 새로 만드는 구성 drift(검증 뒤 상태 변경)도 자동 감시하지 않습니다. 해당 사용자는 계속 키 없이 MFA 브라우저 로그인만 사용해야 합니다.
- IAM Identity Center 신뢰는 단일 현재 역할 ARN이 아니라 같은 계정, AWS 예약 경로와 정확한 permission set 이름을 고정하고 AWS가 역할을 재생성할 때 달라지는 16자리 suffix만 `_*`로 허용합니다.
- 권한 준비 스택은 IAM 사용자·그룹·접근키·콘솔 비밀번호를 만들지 않고, cleanup 및 IAM 변경 권한을 배포 역할에 주지 않습니다. 스택은 create-only이고 역할과 정책은 삭제 때도 `Retain`되므로, 정책 갱신·신뢰 주체 교체·실제 폐기는 [관리자 유지관리 절차](access-bootstrap.md#8-create-only-권한-스택의-갱신과-완전-제거)와 별도 승인이 필요합니다.
- `lab-lightsail`의 자원 생성·태그·방화벽·고정 IP·경보·삭제 권한은 CloudFormation의 전달 요청(`aws:CalledVia`)에서만 허용합니다. 사용자가 Lightsail 쓰기 API를 직접 호출하는 경로로 다른 자원에 파일럿 태그를 붙이거나 삭제할 수 없어야 합니다.
- 직접 운영 권한은 네 개의 파일럿 태그가 이미 있는 인스턴스의 시작·중지·재시작·브라우저 SSH로 제한합니다.
- CloudFormation 스택 삭제와 termination protection(삭제 방지) 해제는 평상시 배포 역할에서 뺍니다. 권장 경로는 승인된 삭제 시간에 비루트 관리자가 정확한 고정 스택만 제거합니다. 기존 직접 IAM 사용자 호환 경로에서만 별도 cleanup 정책을 임시 연결하고 즉시 해제합니다.
- IAM은 로컬 `TemplateBody`의 checksum이나 템플릿 안 Lightsail bundle·자원 개수·월 가격 상한을 검사하지 못합니다. 이 정책은 IAM 차원의 비용 상한이 아닙니다. 고정 스택 이름이 아직 없을 때 배포 역할이 탈취되면 다른 템플릿으로 비용 제한을 우회할 잔여 위험이 있으므로, 검토·Push된 commit의 배포 스크립트만 사용하고 이 역할에 다른 AWS 권한을 추가하지 않습니다.

## 위협과 완화

| 위협 | 완화책 |
|---|---|
| Git에 인증정보 커밋 | Secret 검사, 예제에는 값 대신 설명만 사용 |
| Docker socket 악용 | 전용 호스트, 외부 노출 금지, 고정 이미지, 모니터링 |
| 공급망 변경 | 릴리스·커밋·플랫폼 digest 동시 고정 |
| 위조 또는 잘못된 TLS 인증서 적용 | 공인 CA chain·현재 IP SAN·48시간 유효 여유·개인키 일치·Nginx live 응답을 모두 검증한 뒤 원자 전환 |
| CA 장애·인터넷 단절·rate limit | 6시간 주기와 무작위 지연, 기존 유효 인증서 보존, 실패 표식과 상태 실패. 자체서명 fallback 금지 |
| ACME 계정키·TLS 개인키 노출 | root 전용 디렉터리와 `0600`, 일반 백업·공개 로그 제외, Certbot 컨테이너의 Docker socket·공개 포트 금지 |
| `lab-lightsail` 삭제 또는 덮어쓰기 | 같은 서버의 로컬 백업·자동 snapshot·격리 복원시험. 서버와 함께 잃을 수 있으므로 중요 데이터 보호로는 불충분 |
| `standard-aws` 삭제 또는 덮어쓰기 | S3 Versioning, 별도 DB 백업과 외부 격리 복원시험을 설계 목표로 사용 |
| 기존 업무 DB 오작동 | 자격증명·네트워크·운영 절차 완전 분리 |
| 과도한 AWS 권한 | 서울·고정 스택·자원 형식·태그·CloudFormation 경유 조건, 삭제 권한 분리, 잔여 TemplateBody 위험 명시 |
